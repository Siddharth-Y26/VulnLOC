01

Domain & Problem Statement

5 marks

Software vulnerabilities are defects that an attacker can turn into a capability. The industry's incumbent defence is static analysis, and its incumbent complaint is the false positive rate: an analyser that flags a whole file gives a reviewer a haystack, not a needle. Machine-learning detectors were meant to fix this, and mostly did not — because almost all of them inherited the same output granularity.

The gap, stated precisely

Granularity

The dominant formulation is function-level binary classification: is this function vulnerable? A developer handed “yes” for a 200-line function has been handed the original problem back.

Explainability

Where explanations exist they are usually post-hoc attention heatmaps. Attention is not evidence, and a heatmap is not a reason a developer can act on.

Fusion depth

Semantic (token) and structural (graph) views are both known to help. They are almost always combined by concatenating two pooled vectors — the two modalities never actually interact.

Ground truth

Line-level supervision barely exists. One public C/C++ distribution ships usable per-line labels, and those labels are noisy in ways the literature under-reports.

What this project claims

Both branches are projected onto a shared line axis — every token window and every graph node knows the 1-indexed source line it belongs to — and then allowed to attend to each other in both directions before any pooling happens. The output is a per-line score plus an explanation grounded in the graph evidence that produced it. The load-bearing experiment is deliberately narrow: cross-attention versus plain concatenation, under identical data, encoders, and tuning budget. If cross-attention does not win, that is the reported result.

Three measured ceilings, kept separate

Domain command here means knowing what caps the numbers before running anything. These are three different quantities and must never be merged into one:

  • ~30% of line labels are wrong (human audit, 6 of 20 wrong; 95% CI [14.5%, 51.9%]). This is the ceiling on every line-level metric. It is structurally larger than, and separate from, the 19.2% function-level noise rate.
  • 7.84% of flagged lines carry no AST node at all, so the structural branch cannot score them — 84.8% of those sit in units no grammar parses cleanly.
  • Truncation at 512 tokens destroys 38.1% of flagged lines (44.5% on the clean-eval set). Windowing recovers 100%, and is on by default.

The literature has converged on three separate facts: line-level output is what developers need (A); program structure carries signal that tokens do not (B); and pre-trained code models are strong but not sufficient on their own (D). What nobody has done is let the two modalities interact bidirectionally on a shared line axis before pooling, and then measure that choice against plain concatenation under matched budgets. Group C is the closest, and each entry there either fuses at the function level, or fuses a different second modality, or never runs the controlled comparison. That comparison — experiment A1 — is the contribution. Group E is why we report a label-noise ceiling alongside every number instead of a leaderboard row.

Proposed Methodology

5 marks

The method is one idea applied consistently: make the line the atomic unit everywhere, so that two representations built by completely different machinery become directly comparable.

Why step 5 is the claim, and how it is tested

Concatenation lets a classifier read two summaries. Cross-attention lets the structural view reweight the semantic view line by line — a call on line 10 can be told by the data-flow edges that it consumes a value defined on line 5. Experiment A1 compares cross-attention against concat, sum, gated, and no fusion with identical data, identical encoders, identical training budget, and identical hyperparameter search effort on both sides. Five seeds, mean ± std, significance tested. Giving the novel arm more tuning than the baseline would invalidate the result, so the budget is fixed and documented in advance.

Evaluation, committed before results are seen

Headline line-level metrics

Top-5 accuracy, IFA (initial false alarms — clean lines inspected before the first true one), and line-level PR-AUC. Fixed now to prevent metric-shopping later.

Effort-aware

Recall@k%LOC, MFR/MAR. A reviewer has a budget; recall at an unbounded budget is not a useful claim.

Faithfulness, not just plausibility

Deletion/insertion tests, ERASER-style comprehensiveness and sufficiency, and attention–gradient agreement. Attention is treated as a hypothesis to test, never as an explanation by assumption.

Splits

Project-wise 80/10/10, seed 42, content-hashed rather than shuffled. Zero shared projects, zero cross-split duplicate hashes. Accuracy is reported but never leads.

A negative result is a planned outcome

If cross-attention does not beat concatenation under matched conditions, the project reports that. The contribution is then the controlled comparison plus the line-level evaluation protocol — both of which the literature in section 2 is missing.

5 marks

Seven layers, imports flowing strictly downward, mechanically enforced by import-linter in CI — an upward import fails the build rather than being caught in review. Six registries make every ablation a config change, so no experiment ever edits a .py file.

L0 cannot import L1. That is why the data loader emits an inert LabelledFunction rather than a parse-ready CodeUnit — the boundary is a constraint the type system carries, not a convention.

The module the whole design turns on

models/alignment.py — the LineAligner. It takes token states indexed by window and node states indexed by graph, and returns both indexed by line. Everything upstream exists to preserve the line index; everything downstream exists because the line index survived. All four graph types share one node set, so node_to_line is identical across AST, CFG, DFG and CPG — which is what makes the CPG a literal union rather than a re-derivation.

Reproducibility as a system property

  • The split is content-hashed, not shuffled; re-running the build verifies byte-identity, and a differing assignment is a hard failure rather than a new result. Fingerprint 0ade7483….
  • Every reported number cites an MLflow run ID. A figure with no run behind it does not go in a slide.
  • Checkpointing every N steps, not per epoch — an epoch exceeds 16 minutes, and a run interrupted mid-epoch used to leave nothing on disk.
  • Stubs raise NotImplementedError. Nothing returns a plausible fake tensor.

The representation, rendered from real corpus data

Yes — the graphs are visualizable, and this is them. Below is one function from the test split with all four graph types built from it. The layout is deliberately not a spring layout: the vertical axis is the source line and the horizontal axis is the column within that line. That makes the project's central claim visible rather than asserted — every node sits on the row it belongs to, so the semantic and structural branches have something to meet on. It also makes a line-mapping bug show up as a node on the wrong row, which is the entire reason the renderer exists.

Read the four panels together and the ablation question answers itself. The AST is dense and uniform — it describes syntax, and syntax is present on every line whether or not anything is wrong. The CFG is sparse and vertical, encoding the branch at line 8. The DFG is the interesting one: its edges connect the allocation on line 5 to the uses that follow, which is exactly the shape of a CWE-200 information exposure. The CPG carries all of it on the same 101 nodes. Ablation A3 asks which of these colours the model actually needs — and because they share a node set, that experiment is one config value, not four pipelines.

What the figure also shows, honestly

This unit was chosen by a filter, not by eye: first unit in the test shard between 12 and 34 lines, parsing cleanly, with both CFG and DFG edges present, and with under 35% of its lines flagged. That last condition was added after the first candidate came back with 19 of its 21 lines flagged — a real and common property of a corpus whose labels come from fix commits that rewrite whole functions. That is the ~30% line-noise ceiling from section 1, visible in a single sample.
