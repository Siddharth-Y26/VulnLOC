Since C/C++ dominates line-level vulnerability datasets, these recommendations lean heavily into C/C++, which resolves your open question regarding target language (Q2).  Here are the best datasets available right now for your specific architecture:A. PrimeVulOverview: A recently released (2024) and highly curated dataset designed explicitly to train and evaluate code language models in realistic vulnerability detection settings.Why it fits your project: PrimeVul contains ~7k vulnerable and ~229k benign C/C++ functions. It was constructed specifically to minimize data contamination and address the exact threat to validity you noted in your research plan: label noise from automated commit-diff scraping. It provides highly accurate labels and metadata linking back to original commits.  Link: PrimeVul GitHub RepositoryB. BigVul (The LineVul Standard)Overview: A massive C/C++ vulnerability dataset extracted directly from Common Vulnerabilities and Exposures (CVEs) and GitHub commits.Why it fits your project: This is arguably the most important baseline dataset for line-level tasks. It explicitly includes a flaw_line_index column (the exact index of the vulnerable statement). Using this dataset makes your E3 (LLM-only) and E4 (GNN-only) baseline comparisons immediately credible to reviewers.  Link: BigVul on Hugging FaceC. CVEfixesOverview: A comprehensive, relational database covering over 12,000 vulnerability-fixing commits across 4,200+ open-source projects.Why it fits your project: CVEfixes provides source code at the file and method levels before and after a fix. Because it retains the raw commit diffs, it perfectly supports your assumed strategy in Phase 1 (data/labeling.py): deriving your own line-level labels based on the diffs.  Link: CVEfixes GitHub RepositoryD. DiverseVulOverview: Contains nearly 350K vulnerable and non-vulnerable C/C++ functions, heavily annotated with 150 distinct CWE types.Why it fits your project: In PRD.md (Q5), you ask whether CWE-type classification is required. If you choose to generate explanations that name the specific vulnerability type (e.g., "Buffer Overflow"), DiverseVul's high-quality CWE tagging makes it an ideal pre-training or fine-tuning resource.
